01

Pehle samjho: API, request, response hote kya hain

Is poore course mein hum "API," "request," "response," "JSON" jaise words baar baar use karenge — toh code pe jaane se pehle inhe ek bilkul non-technical example se samajh lete hain, taaki aage kabhi confusion na ho.

Socho tum ek restaurant mein gaye ho. Tum table pe baithe ho (tum yahan customer ho). Tumhe khana chahiye, lekin tum khud kitchen mein jaake nahi bana sakte — ek waiter hai jo tumhare aur kitchen ke beech khada hai. Tum waiter ko apna order bolte ho, waiter wo order kitchen mein chef tak le jaata hai, chef khana banata hai, aur waiter wahi khana wapas tumhare table pe le aata hai.

Customer (tum)→ order →Waiter→ →Chef / Kitchen→ khana →Waiter→ →Customer

Ab in roles ko tech ke terms se map karte hain:

  • Tum (customer) = frontend — jo app ya website tum use kar rahe ho.
  • Chef/kitchen = backend/server — jahan actual kaam hota hai (database check karna, calculation karna, waghera).
  • Waiter = API — frontend aur backend ke beech ka connector. Waiter khud khana nahi banata, wo sirf order le jaata hai aur result wapas le aata hai — API bhi yahi karta hai.
  • Tumhara order ("ek paneer tikka dena") = ek request — tumne kuch maanga.
  • Waiter jo khana le ke aata hai = ek response — jo maanga tha, uska jawaab.
  • Menu card = ek protocol — fixed rules ki tum restaurant mein kya-kya order kar sakte ho aur kaise.
  • Khana jis particular tarike se plate mein saja ke aata hai = data format — tech mein jab data ek fixed, predictable tarike se likha jaata hai (jaise {"dish": "paneer tikka", "price": 220}), usko hum JSON bolte hain. Abhi itna samajh lo ki ye data likhne ka ek standard tarika hai — isme hum age aur detail mein jaayenge.
theek hai? Jab bhi aage "API ko request bheji" ya "API ne JSON response diya" jaisa sentence aaye, wapas is restaurant wale example pe aa jaana — request = order, response = khana, JSON = us khane ko ek fixed, predictable tarike se describe karna.
02

Kyun FastAPI, plain Python se kya problem thi

Ab jab humein pata hai ki API ek connector hai jo requests leta hai aur responses deta hai — maan lo tumhe khud apna "waiter" (API) banana hai Python mein. Plain Python mein (bina kisi framework ke) tumhe khud HTTP request parse karni padegi, JSON validate karni padegi, errors handle karne padenge, aur documentation khud likhni padegi. Har chhoti si cheez manual.

Ab sawaal ye aata hai ki existing Python web frameworks (jaise Flask) ye sab kyun nahi karte automatically? Theek hai, answer hai: wo karte hain request routing, lekin validation aur documentation zyada manual rehte hain. FastAPI ka pura point yahi hai — Python ke type hints use karke validation aur documentation dono automatically generate kar deta hai.

basically FastAPI khud ek naya language nahi seekha raha — jo type hints tum already Python mein likhte ho (def foo(x: int)), FastAPI unhi ko use karke validation aur docs bana deta hai. Yahi uska core idea hai.
03

Pehla app — sirf 5 lines mein

Chalo ek minimal app likhte hain. Pehle install karo:

pip install fastapi uvicorn

Ab main.py mein ye likho:

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "Hello, Virus!"}

Line by line dekhte hain — FastAPI() se ek app instance banta hai, @app.get("/") ek decorator hai jo batata hai "jab koi GET / pe request bheje, ye function chalao," aur function jo bhi Python dictionary return karega, wo automatically JSON mein convert ho jaayega — tumhe manually json.dumps karne ki zaroorat nahi.

04

Chalao aur dekho kya milta hai

FastAPI khud server nahi chalata — uske liye ek separate tool use hota hai jo actually requests sunta hai aur unhe tumhare app tak pahunchata hai.

Browser request→Uvicorn (server)→Tumhara FastAPI app→JSON response 
uvicorn main:app --reload

main:app ka matlab hai "main.py file mein jo app variable hai, wahi chalao." --reload flag development ke liye hai — code change karte hi server khud restart ho jaata hai, production mein ye flag nahi use karte (production setup Lecture 8 mein aayega).

Ab browser mein http://127.0.0.1:8000 khol ke dekho — {"message": "Hello, Virus!"} dikhna chahiye. Aur ek bonus: http://127.0.0.1:8000/docs pe jaake dekho — FastAPI ne automatically ek interactive documentation page bana diya hai, bina tumne kuch likhe.

dhyan rakhna Agar uvicorn: command not found jaisa error aaye, toh confirm karo ki pip install wahi Python environment mein hua jisse tum command chala rahe ho — ye ek bahut common mistake hai jab multiple Python versions ya virtual environments involved hote hain.

Note: yeh code is lecture ko likhte waqt live docs se scrape nahi kiya gaya tha (koi browser tool is demo session mein nahi chalaya gaya) — FastAPI/Uvicorn ka basic setup pattern kaafi stable hai, par agar tum ise kisi bahut naye FastAPI version pe try kar rahe ho, syntax double-check kar lena.

Agle lecture mein hum real endpoints banayenge — path aur query parameters ke saath, aur dekhenge FastAPI type hints se validation kaise free mein milti hai.
