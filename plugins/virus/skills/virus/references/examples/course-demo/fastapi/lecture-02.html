Routing: path aur query parameters

Pichhle lecture mein ek fixed endpoint banaya tha. Aaj dekhte hain dynamic endpoints kaise banate hain — jahan URL ka part ya query string khud data carry karta hai.

01. Path parameters 02. Query parameters 03. Free validation
01

Path parameters — URL ke andar hi data

Maan lo tumhe "ek specific user ki detail do" wala endpoint chahiye — /users/5, /users/42, waghera. Yahan 5 aur 42 ek "path parameter" hain.

@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}

Dekho — {user_id} URL mein ek placeholder hai, aur function ka parameter user_id: int usi naam se match hota hai. FastAPI automatically URL se wo value nikaal ke function ko de deta hai.

theek hai? Type hint (: int) sirf documentation ke liye nahi hai — FastAPI isko actually enforce karta hai. Agar koi /users/abc try kare, automatically ek validation error wapas aayega, tumhe khud check likhne ki zaroorat nahi.
02

Query parameters — optional extra data

Ab maan lo tumhe results limit karne ka option chahiye — /users?limit=10. Ye query parameter hai, path ka part nahi.

@app.get("/users")
def list_users(limit: int = 10):
    return {"limit": limit}
URL: /users?limit=5→FastAPI parses query string→limit=5 as int

Yahan fark ye hai — jo parameter URL path ({...}) mein nahi hai, wo automatically query parameter ban jaata hai. Aur = 10 dene se wo optional ho jaata hai — agar koi limit na de, default 10 use hoga.

03

Ye validation free mein kyun mili

Ab sawaal ye aata hai ki humne kahin explicitly "agar invalid ho toh error do" jaisa code toh likha hi nahi — ye kaam kaise ho raha hai? Theek hai, answer hai: FastAPI tumhare type hints ko padhta hai aur unke base pe Pydantic (ek validation library) automatically use karta hai — iske baare mein agle lecture mein detail se baat karenge jab hum request bodies banayenge.

dhyan rakhna Path aur query parameter dono same naam se function mein aa sakte hain, par agar tumne URL mein {user_id} likha hai, FastAPI use hamesha path parameter maanega, chahe tum query string mein bhi wahi naam bhejo — confusion yahin se aata hai jab naming clash ho jaaye.

Note: yeh lecture bhi live FastAPI docs scrape kiye bina likha gaya hai (demo session mein koi browser tool nahi chalaya gaya) — path/query parameter ka ye basic behavior kaafi samay se stable hai FastAPI mein, par production use se pehle apne installed version ke saath ek baar confirm kar lena.

Agle lecture mein hum request bodies banayenge Pydantic models ke saath — jahan validation aur bhi powerful ho jaati hai, aur response ka shape bhi control kar paayenge.
